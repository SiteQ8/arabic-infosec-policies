# دليل تخصيص سياسات أمن المعلومات
## Customization Guide for Information Security Policies

### مقدمة / Introduction

يهدف هذا الدليل إلى مساعدة المؤسسات العربية في تخصيص سياسات أمن المعلومات لتناسب احتياجاتها الخاصة، طبيعة أعمالها، والبيئة التنظيمية التي تعمل فيها.

---

## فهم عملية التخصيص / Understanding Customization

### لماذا التخصيص مهم؟
- كل مؤسسة لها احتياجات وتحديات فريدة
- القوانين المحلية تختلف من بلد لآخر
- طبيعة الأعمال تحدد مستوى المخاطر والضوابط المطلوبة
- الموارد المتاحة تؤثر على مستوى التطبيق

### مبادئ التخصيص الناجح
1. **التدرج:** البدء بالأساسيات والتطوير تدريجياً
2. **المرونة:** قابلية التعديل والتحسين المستمر
3. **العملية:** سهولة التطبيق والفهم
4. **الامتثال:** توافق مع المتطلبات القانونية والتنظيمية

## خطوات التخصيص الرئيسية / Main Customization Steps

### الخطوة الأولى: التحليل المؤسسي

#### أ) تحديد خصائص المؤسسة
**معلومات أساسية مطلوبة:**
- نوع المؤسسة: [حكومية / خاصة / غير ربحية]
- القطاع: [مصرفي / صحي / تعليمي / تصنيع / خدمات]
- الحجم: [صغيرة < 50 موظف / متوسطة 50-250 / كبيرة > 250]
- النطاق الجغرافي: [محلي / إقليمي / دولي]
- طبيعة البيانات: [شخصية / مالية / طبية / سرية]

**قالب تحليل المؤسسة:**
```
اسم المؤسسة: ________________________
نوع النشاط: ________________________
عدد الموظفين: ________________________
المواقع: ________________________
أنواع البيانات الرئيسية: ________________________
الأنظمة التقنية الحرجة: ________________________
```

#### ب) تحديد البيئة التنظيمية
**القوانين المحلية:**
- قانون حماية البيانات الشخصية
- قوانين الأمن السيبراني
- متطلبات القطاع الخاصة (مصرفي، صحي)
- معايير الجودة والاعتماد

**المعايير الدولية ذات الصلة:**
- ISO 27001 (أمن المعلومات)
- SOC 2 (ضوابط الخدمات)
- PCI DSS (أنظمة الدفع)
- GDPR (الخصوصية الأوروبية)

### الخطوة الثانية: تقييم المخاطر والاحتياجات

#### أ) تحليل المخاطر المحددة
**مصفوفة تقييم المخاطر:**

| نوع المخاطر | احتمالية | تأثير | درجة الخطورة | الأولوية |
|-------------|---------|-------|-------------|---------|
| تسرب البيانات | عالي/متوسط/منخفض | عالي/متوسط/منخفض | حرج/عالي/متوسط/منخفض | 1-5 |
| الوصول غير المخول | | | | |
| انقطاع الخدمة | | | | |
| البرمجيات الخبيثة | | | | |

#### ب) تحديد الضوابط المطلوبة
**تصنيف الضوابط حسب الأولوية:**
- **ضرورية (Must Have):** لا يمكن العمل بدونها
- **مهمة (Should Have):** تحسن الأمان بشكل كبير
- **مفيدة (Could Have):** إضافات مفيدة للمستقبل
- **اختيارية (Won't Have):** غير مناسبة للوقت الحالي

### الخطوة الثالثة: تخصيص محتوى السياسات

#### أ) تخصيص المعلومات العامة
**البيانات الأساسية للتحديث:**
```
[اسم المؤسسة] ← اسم مؤسستك الفعلي
[القطاع] ← قطاع عملك (مصرفي، صحي، إلخ)
[تاريخ الإصدار] ← التاريخ الفعلي
[رقم الإصدار] ← نظام ترقيم مؤسستك
[اسم المسؤول] ← اسم ومنصب المعتمد
[معلومات الاتصال] ← بياناتك الفعلية
```

#### ب) تعديل التعريفات والمصطلحات
**أمثلة للتخصيص:**

**المعلومات الحساسة:**
- **البنوك:** بيانات الحسابات، أرقام البطاقات، السجلات المالية
- **المستشفيات:** السجلات الطبية، معلومات المرضى، البيانات التشخيصية
- **التعليم:** سجلات الطلاب، الدرجات، المعلومات الشخصية
- **الحكومة:** الوثائق السرية، بيانات المواطنين، المعلومات الاستراتيجية

**المستخدم المخول:**
- **تعريف عام:** أي شخص له حق الوصول الرسمي للأنظمة
- **تعريف مخصص:** الموظفون المعينون رسمياً، المقاولون المعتمدون، الشركاء المخولون

#### ج) تعديل مستويات التصنيف
**نموذج تصنيف مخصص:**

| المستوى | الوصف | أمثلة من مؤسستك | الضوابط المطلوبة |
|---------|-------|------------------|-------------------|
| سري للغاية | [وصف مخصص] | [أمثلة فعلية] | [ضوابط محددة] |
| سري | [وصف مخصص] | [أمثلة فعلية] | [ضوابط محددة] |
| محدود | [وصف مخصص] | [أمثلة فعلية] | [ضوابط محددة] |
| عام | [وصف مخصص] | [أمثلة فعلية] | [ضوابط محددة] |

### الخطوة الرابعة: تعديل الأدوار والمسؤوليات

#### أ) هيكل الإدارة التنظيمية
**تخصيص الأدوار حسب الهيكل التنظيمي:**

**للمؤسسات الصغيرة:**
- **مدير عام:** يقوم بدور CISO
- **مسؤول تقنية:** يدير الأمان التقني
- **مسؤول إداري:** يتابع الامتثال والتدريب

**للمؤسسات المتوسطة:**
- **مسؤول أمن معلوماتي:** CISO مخصص
- **فريق تقنية:** متخصص في الأمان
- **مدراء أقسام:** مسؤولية امتثال أقسامهم

**للمؤسسات الكبيرة:**
- **إدارة أمن معلوماتي:** قسم مستقل
- **مركز عمليات أمان:** SOC
- **لجنة حوكمة:** على مستوى مجلس الإدارة

#### ب) تحديد المسؤوليات الخاصة
**أمثلة للتخصيص:**

**القطاع المصرفي:**
- مسؤول امتثال PCI DSS
- مدير أمان العمليات المالية
- محلل مخاطر ائتمانية

**القطاع الصحي:**
- مسؤول خصوصية المرضى
- أمين السجلات الطبية
- مدير أمان الأجهزة الطبية

## تخصيص القطاعات المختلفة / Sector-Specific Customization

### القطاع المصرفي والمالي

#### متطلبات خاصة:
- الامتثال لمعايير PCI DSS
- حماية البيانات المالية
- أمان العمليات المصرفية الإلكترونية
- إدارة مخاطر الاحتيال

#### تعديلات مطلوبة:
```
تصنيف البيانات:
- سري للغاية: بيانات الحسابات، أرقام البطاقات
- سري: السجلات المالية، تقارير الائتمان
- محدود: معلومات العملاء العامة
- عام: المعلومات التسويقية

ضوابط خاصة:
- مصادقة قوية للعمليات المالية
- تشفير end-to-end للمعاملات
- مراقبة مستمرة للأنشطة المشبوهة
- احتفاظ بالسجلات لمدة [حسب القانون المحلي]
```

### قطاع الرعاية الصحية

#### متطلبات خاصة:
- حماية خصوصية المرضى
- أمان الأجهزة الطبية المتصلة
- سرية السجلات الطبية
- الامتثال للمعايير الصحية

#### تعديلات مطلوبة:
```
تصنيف البيانات:
- سري للغاية: السجلات الطبية الكاملة
- سري: نتائج التحاليل والفحوصات
- محدود: المعلومات الإدارية للمرضى
- عام: المعلومات الصحية التثقيفية

ضوابط خاصة:
- تشفير السجلات الطبية
- ضوابط وصول صارمة للبيانات الطبية
- تدريب خاص للكوادر الطبية
- نسخ احتياطية آمنة للسجلات الحرجة
```

### القطاع الحكومي

#### متطلبات خاصة:
- حماية المعلومات الحكومية السرية
- الامتثال للأنظمة الحكومية
- أمان الخدمات الحكومية الإلكترونية
- حماية بيانات المواطنين

#### تعديلات مطلوبة:
```
تصنيف البيانات:
- سري للغاية: المعلومات الأمنية والاستراتيجية
- سري: بيانات المواطنين الشخصية
- محدود: المعلومات الإدارية الداخلية
- عام: المعلومات المتاحة للعموم

ضوابط خاصة:
- تصنيف أمني للموظفين
- أنظمة اتصال آمنة
- حماية متقدمة للبنية التحتية الحرجة
- إجراءات طوارئ وطنية
```

### القطاع التعليمي

#### متطلبات خاصة:
- حماية بيانات الطلاب والدرجات
- أمان أنظمة التعلم الإلكتروني
- إدارة وصول متعدد المستويات
- حماية البحوث والملكية الفكرية

#### تعديلات مطلوبة:
```
تصنيف البيانات:
- سري للغاية: نتائج الامتحانات، السجلات التأديبية
- سري: بيانات الطلاب الشخصية، الملفات الأكاديمية
- محدود: المعلومات الإدارية، جداول الحصص
- عام: المواد التعليمية، الإعلانات

ضوابط خاصة:
- ضوابط وصول مرنة للطلاب والمعلمين
- حماية أنظمة التعلم عن بُعد
- أمان شبكات الحرم الجامعي
- حماية البحوث والمشاريع الأكاديمية
```

## التخصيص حسب حجم المؤسسة / Size-Based Customization

### المؤسسات الصغيرة (أقل من 50 موظف)

#### الخصائص المميزة:
- موارد محدودة
- بساطة في الهيكل التنظيمي
- اعتماد على حلول خارجية
- مرونة في التطبيق

#### استراتيجية التخصيص:
```
الأولويات:
1. السياسات الأساسية فقط
2. ضوابط الوصول البسيطة
3. نسخ احتياطية أساسية
4. تدريب أساسي للموظفين

التبسيطات المقترحة:
- دمج عدة أدوار في شخص واحد
- استخدام قوالب جاهزة
- الاعتماد على خدمات سحابية
- سياسات مبسطة وواضحة
```

### المؤسسات المتوسطة (50-250 موظف)

#### الخصائص المميزة:
- موارد معتدلة
- هيكل تنظيمي متوسط التعقيد
- مزيج من الحلول الداخلية والخارجية
- حاجة لتوازن بين الأمان والتكلفة

#### استراتيجية التخصيص:
```
الأولويات:
1. معظم السياسات الأساسية
2. نظام إدارة هوية مركزي
3. مراقبة أساسية للأمان
4. برنامج تدريب منتظم

التحسينات المقترحة:
- فريق أمان صغير متخصص
- أنظمة مراقبة متوسطة التعقيد
- سياسات مفصلة ولكن عملية
- شراكات مع مختصين خارجيين
```

### المؤسسات الكبيرة (أكثر من 250 موظف)

#### الخصائص المميزة:
- موارد كبيرة
- هيكل تنظيمي معقد
- حلول داخلية متقدمة
- متطلبات امتثال صارمة

#### استراتيجية التخصيص:
```
الأولويات:
1. جميع السياسات بالتفصيل
2. أنظمة أمان متقدمة ومتكاملة
3. مركز عمليات أمان (SOC)
4. برامج تدريب متخصصة ومستمرة

التقدم المطلوب:
- قسم أمان مستقل
- تقنيات متقدمة (AI، Zero Trust)
- سياسات شاملة ومفصلة
- امتثال كامل للمعايير الدولية
```

## التخصيص التقني / Technical Customization

### تخصيص الضوابط التقنية

#### أ) أنظمة التشغيل
**Windows Environment:**
```
Group Policy Settings:
- Password policies
- Account lockout policies
- Audit policies
- User rights assignment
```

**Linux Environment:**
```
Security Configurations:
- PAM settings
- Firewall rules (iptables/firewalld)
- SELinux policies
- Log monitoring (rsyslog/systemd)
```

#### ب) قواعد البيانات
**SQL Server:**
- Transparent Data Encryption (TDE)
- Always Encrypted
- Row Level Security
- Audit specifications

**Oracle:**
- Oracle Advanced Security
- Database Vault
- Label Security
- Audit Vault

#### ج) الشبكات
**Cisco Environment:**
- ASA firewall rules
- IOS security features
- Network segmentation (VLANs)
- AAA authentication

**Microsoft Environment:**
- Windows Firewall
- Network Access Protection
- DirectAccess/VPN
- Network Policy Server

### تخصيص أدوات المراقبة

#### حسب البيئة التقنية:
**Microsoft Environment:**
- Microsoft 365 Defender
- Azure Sentinel
- System Center Operations Manager
- Windows Event Forwarding

**Mixed Environment:**
- Splunk Enterprise
- IBM QRadar
- Elastic Stack (ELK)
- Open source tools (OSSIM, OSSEC)

## الدعم والاستشارة / Support & Consultation

4. **دعم التطبيق:** مساعدة في مرحلة التنفيذ
